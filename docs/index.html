возможности

Доказательства вместо обещаний

Noema превращает разговор с моделью в проверяемый инженерный процесс: у каждого утверждения есть вердикт, у каждого шага — след.

Доказательства вместо обещаний

Гипотеза получает статус результата только после проверки Z3: контрпримеров нет — обещание стало доказательством.

Audit trail каждого шага

Требование, гипотеза, вердикт, патч — записаны и воспроизводимы. Разбор инцидента начинается с фактов, а не с догадок.

Sandbox-рантайм

Кандидат исполняется в изоляции до публикации. Непроверенный код не доезжает до продакшена.

Автономное исправление инцидентов

Noema находит причину, готовит патч и открывает pull request с доказательством, что исправление проходит те же контракты.

Контракты как код

Бюджеты, пороги и границы действий — поля контракта. Изменение требования — ревьюируемый коммит, а не сообщение в чате.

12 демо без ключей

Живые демо запускаются без API-ключей: контракты, Z3 и песочница уже в репозитории.

как это работает

Четыре остановки от требования до результата

Маршрут один и тот же для любой задачи: зафиксировать требование, получить гипотезу, проверить её контрактом, опубликовать результат.

01 · требование → контракт

Требование фиксируется контрактом

Бюджеты, пороги и границы действий становятся числовыми полями контракта. Требование перестаёт быть туманным абзацем в чате.

  • ограничения — проверяемые поля
  • изменение требования — новый коммит
02 · гипотеза → кандидат

LLM предлагает решение

Модель генерирует код, план или конфигурацию. Её ответ — гипотеза без права считаться результатом: ни один кандидат не проверяет сам себя.

  • кандидаты сохраняются и воспроизводимы
  • отклонённые гипотезы остаются в истории
03 · гипотеза × контракт → вердикт

Z3 проверяет по контрактам

Солвер Z3 сравнивает гипотезу с контрактом. Контрпримеров нет — гипотеза становится результатом. Контрпример есть — система называет точные условия, где обещание ложно.

  • контрпримеры вместо «что-то не так»
  • исполнение кандидата — только в sandbox
04 · патч → pull request

Инциденты чинятся через pull requests

Когда инцидент случается, Noema находит причину, готовит исправление и открывает pull request с доказательством, что патч проходит те же контракты.

  • автономно — от сигнала до ревью
  • аудит-след каждого шага

Первая проверка — в одну команду.
